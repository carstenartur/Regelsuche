# Exact paired TRAIN fitness for evolved rewrite programs

Status: production-search fitness foundation for #521

## Candidate identity

A learned search strategy is not identified by its rule genome alone.
`EvolutionRewriteProgramCandidate` binds two immutable objects:

- the exact `EvolutionGenome` containing executable rule templates;
- the exact `EvolutionRewriteProgramPlan` describing how those rules are
  sequenced, guarded, repeated, prioritized and pruned.

The combined candidate has its own exact content hash and alpha-structural hash.
The latter combines the genome and topology alpha identities, so population
diversity can distinguish a different strategy while suppressing renaming-only
duplicates.

The strict candidate contract is
[`regelsuche-evolution-rewrite-program-candidate-v1.schema.json`](schemas/regelsuche-evolution-rewrite-program-candidate-v1.schema.json).

## Frozen TRAIN suite

`EvolutionRewriteProgramTrainSuite` is separate from the older flat-genome
suite because flagship cases require explicit mathematical assumptions and an
independent evaluator profile.

Version 1 fixes:

```text
EXACT_RATIONAL_NORMAL_FORM_WITH_DECLARED_ASSUMPTIONS
```

Every case retains:

- case and structural-family identity;
- input and target expression;
- normalized declared assumptions;
- one shared search heuristic.

The artifact is structurally `evaluationSplit=TRAIN`. It contains no
VALIDATION or FINAL TEST case or outcome.

The strict suite contract is
[`regelsuche-evolution-rewrite-program-train-suite-v1.schema.json`](schemas/regelsuche-evolution-rewrite-program-train-suite-v1.schema.json).

## Information-parity execution

`RewriteProgramTrainFitnessEvaluator` executes each case twice:

1. the bounded default AST-rule engine;
2. the same bounded default engine plus exactly one compiled evolved program.

Both runs receive the same:

- source and syntax-exact target;
- assumptions;
- scorer and canonicalizer;
- best-first implementation;
- depth, visited-state, expansion and candidate budgets.

The candidate side differs only through the added `ProgrammedTransformationEngine`.
The program sources may not observe a wider candidate set than the frozen
suite. A suite candidate boundary narrower than the genome source boundary is
retained as a hard blocker.

## Exact path audit

Target reachability is diagnostic search evidence, not mathematical truth.
Whenever a run reaches the target, the evaluator audits every adjacent
expression in the retained path with exact rational-function normal forms and
the task assumptions.

The controlled path statuses are:

- `CONFIRMED`;
- `REFUTED`;
- `MISSING_ASSUMPTION`;
- `UNSUPPORTED`;
- `NOT_EVALUATED` for an unreached path.

The reached state also retains assumptions generated by applied rules. Those
assumptions must be covered by the task's declared assumption set. A path that
requires an undeclared condition fails closed as `MISSING_ASSUMPTION`.

A case is `newlySolved` only when all of the following hold:

- the baseline did not reach the target;
- the candidate reached it;
- at least one retained path edge is an actual `program:` transformation;
- the complete reached path is `CONFIRMED`.

Thus an unsafe evolved rewrite can physically reach the expected string, but it
contributes zero support and zero newly-solved fitness and creates a
`TRAIN_CORRECTNESS_FAILURE` blocker.

## Resource and path accounting

The evidence keeps baseline and candidate values separately:

- search-edge path length;
- primitive step count, expanding composed `program:[a -> b -> ...]` edges;
- explored states;
- generated transformations;
- whether the program was actually used;
- reachability regression;
- correctness failure and confirmed-to-failed correctness regression.

Primitive step reduction rather than macro-edge compression feeds the
`TRAIN_PATH_LENGTH_REDUCTION` component. A two-step program hidden behind one
search edge therefore does not fabricate a one-step computational saving.

The retained raw fitness components remain separate from any scalar population
profile. Unsupported components are zeroed and blocked rather than invented.

The strict evidence contract is
[`regelsuche-evolution-rewrite-program-train-fitness-v1.schema.json`](schemas/regelsuche-evolution-rewrite-program-train-fitness-v1.schema.json).

## Example

A guarded two-stage cancellation program can execute:

```text
(x*y)/(x*1)
  -- cancel_factor, requiring x != 0 --> y/1
  -- divide_one ----------------------> y
```

With search depth fixed to one, the primitive baseline cannot complete both
steps. The program can expose their composition as one replayable search edge,
while evidence still counts two primitive operations. The case counts as newly
solved only after exact rational validation under `x != 0`.

## Claim boundary

This layer establishes paired, assumption-aware TRAIN fitness for one exact
rule-genome/program-topology candidate. It does not perform population
selection, VALIDATION selection, FINAL TEST evaluation, proof, external novelty
review or release promotion.

The next #521 slice must preserve the combined candidate identity through
population reports and checkpoints. Only after that integration is green may
the concrete flagship TRAIN/VALIDATION/FINAL TEST corpus and numerical success
thresholds be frozen before evaluated search begins.
