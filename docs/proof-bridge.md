# Proof-Bridge: Lean & SMT

Die `ProofBridge`-Schnittstelle (`app/src/main/java/de/regelsuche/proof/`) ist die Brücke zwischen dem Regel-Lifecycle (`CandidateProofStatus`) und externen Beweisprüfern.

## Ablauf

1. `ProofBridge.prove(left, right, assumptions)` erzeugt ein Skript in der Zielsprache und liefert einen `ProofAttempt(status, artifact, tool)` zurück.
2. `ProofBridgeService.attempt(candidate, assumptions)` ruft die Bridge auf und hebt – falls erfolgreich – den `CandidateProofStatus` an. Der Service senkt **nie** einen bereits höheren Status (`FORMALLY_PROVED` bleibt erhalten, auch wenn die Bridge nur `FORMALLY_PROVABLE` zurückgibt).
3. Optional: Wird ein `artifactDirectory` an `ProofBridgeService` übergeben, schreibt der Service die Skripte als `.lean` bzw. `.smt2` auf die Platte.

## Bestehende Bridges

### `LeanProofBridge`

Erzeugt ein Lean-4-Theorem-Skelett:

```lean
-- Auto-generated by Regelsuche LeanProofBridge
-- left  : a / b * b
-- right : a
-- assume NON_ZERO(b != 0)
theorem regelsuche_lemma (h0 : b ≠ 0) : a / b * b = a := by
  sorry
```

Status nach Aufruf: `FORMALLY_PROVABLE`. Das Skelett enthält bewusst `sorry`; die Bridge führt Lean nicht aus. Der Workflow ist:

1. Skelett erzeugen (Bridge)
2. In ein Lean-Projekt einchecken
3. `sorry` durch tatsächlichen Beweis ersetzen
4. Bei Erfolg den Kandidaten manuell auf `FORMALLY_PROVED` hochstufen

### `SmtProofBridge`

Erzeugt ein SMT-LIB-2-Skript für QF_NRA:

```smt
(set-logic QF_NRA)
(declare-const a Real)
(declare-const b Real)
(assert (distinct b 0))
(assert (not (= (/ (* a b) b) a)))
(check-sat)
(exit)
```

Liefert das Skript an einen Solver (z. B. Z3, CVC5). Antwortet der Solver mit `unsat`, ist die Äquivalenz bewiesen. Auch hier ruft die Bridge den Solver nicht selbst auf – das ist bewusst so, weil JVM-native Einbindungen plattformabhängig sind.

## Eigene Bridge schreiben

Implementiere `ProofBridge` und gib einen passenden `ProofAttempt` zurück. Konvention für das `tool`-Feld:

* `"lean4"` → Dateiendung `.lean`
* `"smtlib2"` → Dateiendung `.smt2`
* Sonst → Dateiendung `.txt`

Der `ProofBridgeService` setzt diese Endung beim Schreiben auf Platte.

## Zusammenspiel mit Assumptions

Beide Bridges nehmen die `List<Assumption>` der Kandidatenregel entgegen. Sie übersetzen die kanonischen Kinds (`NON_ZERO`, `POSITIVE`, `NON_NEGATIVE`, `DOMAIN`, `CUSTOM`) in die Zielsprache. Wer eigene Assumptions definiert, sollte die `symbols()`-Liste setzen, damit die Bridges sie korrekt referenzieren können.
