# Performance & Coverage Dashboards

Regelsuche publishes three live quality dashboards from CI:

| Dashboard           | URL                                                                | Source                                          |
| ------------------- | ------------------------------------------------------------------ | ----------------------------------------------- |
| Coverage report     | <https://carstenartur.github.io/Regelsuche/coverage/>              | JaCoCo HTML, generated by `./gradlew jacocoTestReport` |
| Test report         | <https://carstenartur.github.io/Regelsuche/tests/>                 | Gradle JUnit HTML, generated by `./gradlew test`       |
| Performance charts  | <https://carstenartur.github.io/Regelsuche/dev/bench/>             | JMH JSON, deployed by `benchmark-action/github-action-benchmark` |

The shields.io endpoint badges in the README (`Coverage`, `Tests`,
`Benchmarks`) consume the same artifacts and therefore always reflect the
last green run on `main`.

## Local commands

```bash
# Coverage report (writes app/build/reports/jacoco/test/)
./gradlew test jacocoTestReport

# Micro-benchmarks (writes app/build/reports/jmh/result.json)
./gradlew :app:jmh
```

The benchmark suite lives in `app/src/jmh/java/de/regelsuche/benchmark/`
and covers the three hottest layers exercised by every search:

* `ExpressionCanonicalizer.canonicalize` – called for every visited state.
* `EGraph.rebuild` – congruence closure after rule application.
* `AstRewriteTransformationEngine.transform` – atomic rewrite expansion.

Add a new `@Benchmark` method whenever you optimise a hot path so the
regression is automatically tracked across commits.

## Why this layout?

The split between three GitHub Pages directories
(`/coverage`, `/tests`, `/dev/bench/`) mirrors the layout used by the
sibling projects
[Taxonomy](https://github.com/carstenartur/Taxonomy) and
[sandbox](https://github.com/carstenartur/sandbox), keeping the cross-repo
experience consistent. The `benchmark-action/github-action-benchmark`
action then provides historical trend lines and regression alerts at the
`/dev/bench/` URL without us having to maintain any custom JavaScript.
