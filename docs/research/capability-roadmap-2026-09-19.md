# Capability roadmap after learning integration

The engineering goal is that growing **validated** knowledge reduces the work
needed for a verified result and makes deeper tasks reachable at the same budget.
The current small transfer studies establish useful pieces of this behavior;
they do not establish broad superiority over other systems.

## Execution order and decision measurements

1. **Inventory scaling (#696).** Compare unfiltered and indexed execution with
   identical ordered successors, primitive replay and bounds. Measure index
   construction separately, matching admissions, repeated execution time and
   the same-operator control. The first implementation is opt-in; its
   [retained measurements](../../research/benchmarks/rule-shape-index/README.md)
   include benefits on large sparse inventories and regressions on small ones.
   Custom compiled genome rules still use fallback dispatch; indexing those
   requires a separately qualified structural contract.
2. **Knowledge utility (#696/#1026).** Grow frozen validated inventories and
   problem depth together. Measure useful reach per total work, matching and
   replay cost, and unused generated successors. Retain primitive, learned,
   shuffled and no-match controls. Avoid granting a multi-step macro free work.
3. **Plan composition (#874).** Learn structural intermediate goals and checked
   plan continuations instead of requiring an externally supplied schedule.
   Hole solving and failed obligations are charged. Require actual use of the
   frozen plan on a different family, beyond a syntactic renaming.
4. **State reuse (#661/#696).** On demonstrated transposition-heavy tasks,
   preserve assumptions/controller state and non-dominated path budgets while
   collapsing future-equivalent arrivals. Compare reachable results with the
   bounded reference before measuring speed.
5. **External and held-out evaluation (#750/#748/#730/#235/#533/#220).** Freeze
   inputs, information, controls and implementation first. Report success rate,
   work to the same verified result, runtime/allocation separately, learning
   cost and amortization, and every failed/inconclusive case.

An index improves execution throughput; a learned plan can reduce how much
search is required. Both matter. Neither a faster lookup nor a longer macro by
itself proves greater mathematical capability. The decisive evidence is more
verified tasks reached under an unchanged, fully accounted budget.
