# Work accounting on the public SymPy preparation panels

This companion measurement for [#730](https://github.com/carstenartur/Regelsuche/issues/730) uses the eleven public amplification sources and the separate nine guard sources from [#1203](https://github.com/carstenartur/Regelsuche/pull/1203). Their outcomes are already public. It is a retrospective cost measurement on the existing panels. The cases, rule inventory, profiles, budgets, principal replay, expected expressions and guards keep their original definitions.

## Units and denominators

Run every source against each of the three principals under all four cumulative profiles. Keep every attempted decision, including early successes, failed searches and exhausted budgets. Within a profile charge each stage when actually invoked. A stage's incremental coverage is the first profile that produces the same qualified consequence for that source and principal. Report the two panels separately.

Freeze the source-only decisions before comparing their assumptions and expressions to the case. Count a candidate under its input only when its retained premises are supported by the input. Record additional and contradicted premises separately. A reusable preparer helps a principal only within the stated qualification category. An exact specialist can receive credit only if it ran.

Retain matching, dispatch, expanded states, generated transitions and primitive path steps as separate units. For local search record the AST sizes at observed inspection points and specify the population for the maximum. Distinguish endpoint size change from growth during search. Count actual certificate-verifier invocations, replay of preparation steps, terminal matching and principal replay. Include failed attempts and repeated verification by the public coordinator. Attribute a complete second formation run to reproducibility and keep it separate from checking the retained certificate. Do not convert counts to elapsed time or infer unobserved work inside SymPy.

## Reproduction and interpretation

Compare instrumented and ordinary decisions for the same inputs and revision, including the selected stage, obligations and certificate identities. Retain the original report formats. Generate a separate `stage-attribution.json`. Require identical bytes from two clean host runs and the pinned comparative runtime image before reporting final measured costs. A bounded gain or a null result is admissible on each panel. The two panels do not estimate a population success rate.
