# Finite-budget modular-program transfer

This public v3 panel grows the number of distinct product-exponent output sites
from one to two and four. Each size has forward and reversed positive shapes,
a no-reuse control, and a control with the positive-modulus premise removed.
The latter must reject every rewrite. Some distractor pairs share factors or
intermediate values. All genuine savings, including discoveries on no-reuse
controls, must be reported. The grammar is one rewrite anywhere in the
original program. Further rewrites of descendants in a new state are outside
this experiment. The source is always available.

## Arms and independent reference

Both arms use the two unchanged product-composition orientations and concrete
replay. The primitive scheduler scans original output roots in order, matches
the common left side once per root with the exact ExprMatcher and emits both
orientations in left/right order. The corpus contains no nested modular powers
in its sources. Cross-check all primitive targets against full
AstRewriteTransport generation over every subtree before interpreting results.
Use complete primitive enumeration **outside** both charged arms to establish
the optimal historical DAG proxy. No target or optimum is passed to a scheduler.

The learned arm prepends one complete arithmetic-AC TypedOutputPattern match
and checks/scores its proposals in their original order. It then executes the
identical primitive scheduler. Each arm discards structurally duplicate proposals
after charging generation, before replay. Only a verified strict DAG improvement
changes the incumbent. Retain its first work point and every later improvement.
Run no target-specific early stop. Raw ledgers include failed attempted matches,
unapproved rewrites and incompletely affordable outcomes.

## Work and decision

Each bound in protocol.json is an identical finite allowance of logical work
points. Basic units are one scheduler match attempt (one output or one injective
assignment), each native matcher evaluated step and structural branch, one
generated candidate, one independent replay request and one DAG score. Source
score costs one point. A compound matcher call becomes visible only after all
of its actual work is charged. A target becomes visible only after its full
generation, replay and scoring prefix fits. Prefixes of a deterministic full
trace reproduce the bounded incumbents; this models admission at action
boundaries and does not bound JVM instructions, elapsed time or memory.
Report dimensions separately because they have different physical costs.

For acquisition, run the original frozen TRAIN and SHUFFLED routine in a
separate process. Charge its actual primitive generator invocations, proposals,
independent replay requests, score calls, example constructions, generalizer,
serialization and decode calls as distinct logical work items. Count the
generator's shared-LHS exact matcher attempts/steps/branches in a separate
TRAIN replay using the TEST scheduler, with the original TRAIN and each broken
relationship. State this proxy explicitly: the original transport itself
folds traversals and has no equivalent native per-match counter. Verify
equivalence of its candidate set, never train on TEST.

Report three views: an already acquired model, all acquisition charged on each
single job, and a stream where acquisition is charged once across all 12 rows
in the frozen file order. The stream spends budget per entire ordered batch,
finishing each job's search before the next starts. Retain the complete
cumulative first-hit work needed to reach each positive reference optimum in
that stream. Report both the raw work-to-first-optimum and finite-budget
wins, ties and losses. A benefit requires a strict verified optimum-reach
advantage at a declared budget, and any amortized claim must include
acquisition and all rows. A tie or loss remains a reported outcome. Never
infer a speedup or general superiority from these logical weights.

The v1 training data, model and v2 public results remain frozen. The two
separate processes for OFFICIAL TRAIN and TEST additionally verify source and
model hashes. Repeat TEST in two JVMs and require identical deterministic
result bytes. Domain checks and independent replay apply before scoring.
