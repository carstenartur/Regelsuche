# Executing exact sharing on external arithmetic expressions

This public development study contributes to [#750](https://github.com/carstenartur/Regelsuche/issues/750). The existing source-only extractor ranks repeated structures. We test whether its first exact material candidate saves executed arithmetic on previously untested benchmark files when translated into a single reusable definition. There is no training in this study.

## Inputs and freeze

Use FPBench commit `090d81982edc0d2a597f4c15644253d4f266a6ef`. Take every `benchmarks/*.fpcore` file at that revision except the three files already retained by the repository's Enumo experiments (`rosa`, `hamming-ch3`, `fptaylor-extra`). The ten files are apron, daisy, fptaylor-real2float, fptaylor-tests, graphics, herbie, ml-frameworks, precimonious, rump and salsa. Retain every top-level program and every rejection from the existing `FpcorePolynomialCorpus.read` projection. A file-wide reader failure is reported as such and precludes a complete-corpus conclusion. Pin the input hashes and publish this protocol and executable evaluator before opening or running the ten files for this study. The upstream data are public.

## Procedure and criteria

- Apply the unchanged default `RepeatedStructureExtractor` to each admitted exact polynomial expression. In its existing order choose the first material candidate accepted by `ExactSharingRepresentation.create`. Keep the direct calculation when none qualifies. Bind the chosen candidate, definition, occurrence paths and normalized input to each positive row. Retain rejected exact overlays. Source labels and observed costs do not affect selection.
- Compare three executions on the same rational expression: the original expression tree, the selected single definition reused at its certified occurrences, and an independent conventional common-subexpression elimination (CSE) control that memoizes all structurally identical operations. Count each executed binary arithmetic instruction once, recording reference uses separately. Literals and variable reads do not count as arithmetic. Preserve operand order and exact rational semantics.
- Assign variables in lexicographic order, indexed from zero. For each row evaluate four substitutions `x_i = (k+1)*(i+1)/2` for `k = -2,-1,0,1`. Check every output against independent direct exact AST evaluation, including domain failure. Recheck the original tree by reconstruction from the selected definition. Keep the full CSE result even when it beats the selected plan.
- The prespecified material threshold is at least two arithmetic operations and at least 10% saved relative to the tree on an external program. Report counts for all programs, supported rows, rows meeting the threshold and per-file sums. Report weaker savings and failures. Repeat the complete runner in two fresh JVMs and compare canonical evidence bytes.
- A measured reduction applies to execution of the expanded exact expression after preparation. The FPCore projector expands `let` bindings and excludes unsupported syntax. These counters do not measure FP runtime, original let-preserving code, compile-time amortization, superiority to ordinary CSE, or learned transfer. The complete issue's held-out formation and equal-work comparison remain separate.
