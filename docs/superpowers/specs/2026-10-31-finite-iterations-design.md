# Verified finite sums and recurrences

The user approved implementing the discussed mathematical generalization and its Java adapter on 2026-10-31. Regelsuche owns the mathematical representation, candidate construction and independent proof. Sandbox owns Java admission, effects, termination, emission and source replay.

## First supported fragment

Introduce an immutable finite-iteration AST alongside the existing scalar `Expr` AST. Its scalar children remain `Expr`; do not force every existing scalar engine to silently interpret a binder. Use scoped symbol identities for bound index/state variables. Model a counted index range (start, nonzero step, nonnegative count), finite sums, and ordered scalar recurrences. Explicit semantics distinguish exact integers, Java int and Java long modular arithmetic. The first executable range has constant integer bounds/count; free scalar parameters may occur in terms and initial values. Symbolic bounds, products, nonlinear recurrences, floating-point reassociation and infinite series are deferred explicitly.

For integer polynomial summands, construct a polynomial antidifference and a closed form. An independent bounded checker must verify the telescoping identity, endpoints, source binding, initial value and arithmetic semantics without invoking candidate search or trusting its status. Ordered recurrences are reducible only when their update normalizes to the old state plus an index polynomial independent of that state. The modular arithmetic bridge is sound only for same-width ring operations; no Java division or mixed-width arithmetic may slip through it. Candidate coefficients must be integral before word reduction.

This supports sums of constants, arithmetic progressions, squares and other bounded-degree polynomials, including invariant input parameters and nonzero initial accumulators. It is not a hard-coded `1..100` rule. Proof work depends on expression size/degree, not on executing the source loop. All admission, polynomial growth, proof, evaluation and cancellation paths are bounded.

## Java boundary

Admit canonical `for` loops with a local int counter, constant integral bounds, comparison `<`, `<=`, `>` or `>=`, and a unit increment/decrement. Prove the update after the last iteration remains representable; reject wrapping/nonterminating counters. The body must contain exactly one assignment to an existing local int/long accumulator, using total same-width polynomial arithmetic and invariant local/parameter inputs. Admit `+=`, `-=`, and an equivalent explicit assignment where safe. Reject fields, arrays, calls, abrupt completion, extra effects, nested control, externally observable counters, floating point, comments that would be lost, and ambiguous/recovered bindings.

Replace the loop with an accumulator assignment using the SDK result. Reparse and decode the actual emitted expression, reverify it against the original recurrence, replay the source admission and variable bindings, and check combined edits. Keep numerical iteration evidence distinct from scalar proof evidence and source scheduling evidence. Reports must carry the new proof and honest estimated cost. Do not fabricate an existing scalar verification receipt for a loop.

## Acceptance and non-goals

`int sum=0; for(int i=1;i<=100;i++) sum+=i;` reduces to a single calculation whose contribution is 5050. Also verify descending ranges, empty/singleton ranges, nonzero initial state, polynomial and parameterized terms, int/long accumulator wrapping, and rejection of counter wrap. A bounded runtime-variable upper limit is not claimed in this release. Negative tests, certificate tampering tests and compiled Java equivalence tests are mandatory. Infinite series later require a distinct limit/convergence contract; an unbounded loop is not such a contract.

Maven/JUnit are authoritative. Use source-qualified reproducible SDK distribution and pinned source receipts. Keep ordinary PRs against current main, one per repository, within the repository review-size policy. No merge is authorized by this implementation request.

## Implemented mathematical limits

The initial provider accepts scoped `SymbolId` occurrences only, with an explicit immutable set of at most 16 free parameters. Index and state binders must be distinct and absent from that set. Initial values may refer only to free parameters. Each scalar source tree is limited to 2048 occurrences, depth 64 and 4096-bit rational numerators/denominators; function metadata is capped at 128 characters before unsupported functions are rejected by search. Range start, nonzero step and nonnegative count each have a 1024-bit limit. These are counted mathematical ranges; the Java adapter must independently establish nonwrapping counter termination.

The executable source/result fragment is integer leaves and `+`, `-`, `*`, with total degree at most 8. Powers, division, functions and fractional source/emitted leaves are rejected, even if cancellation would make the final expression integral. Internal antidifferences may have rational coefficients and total degree 9. Every polynomial is limited to the smaller of 256 monomials and the supplied optimization budget's `maximumStates`, and every intermediate rational coefficient is limited to 4096 bits. Arithmetic temporaries combine only already bounded operands. Search generates at most one candidate (`maximumCandidates` is consequently always respected), charges deterministic polynomial work and checks cancellation/thread interruption and the budget timeout. Proof uses a fresh budget, validates the untrusted certificate/emitted AST, and never invokes synthesis. Candidate work/cost fields are informational; proof recomputes costs.

Only additive recurrences whose normalized update minus old state is independent of that state are admitted. Polynomial identities and integrality are checked over exact rationals before signed coefficient normalization modulo 2^32/2^64. The result contains only scalar integer operations and free parameters; evaluating those operators in the selected Java ring preserves the identity. Operation costs count arithmetic AST operators (plus the accumulation addition for a sum), include recurrence initial expression operations, and exclude loop control, loads, casts and runtime/compiler optimization. A failed verification has no cost. Unsupported/over-budget searches return an empty candidate with a reason, invalid model/scope construction throws an exception, and no such outcome claims a verified identity.
