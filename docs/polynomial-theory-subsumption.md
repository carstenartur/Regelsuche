# Polynomial theory subsumption and derived macro cache

## Purpose

Regelsuche can discover or learn a concrete polynomial rewrite that is already
an instance of a configured exact factorization theory. Such an observation can
still be useful as a search accelerator, but it must not be represented as a new
kernel law or as mathematical novelty.

The current boundary is:

```text
observed or learned identity
  -> typed factorization request
  -> untrusted engine proposals
  -> independent product verification
  -> theory-subsumption decision
  -> optional derived macro cache
  -> no automatic kernel or standard-inventory promotion
```

The implementation addresses the theory-subsumption and bounded-cache portion
of issue #748 on top of the domain-aware architecture from issue #763. Product
default integration, held-out utility comparison and broader factorization
engines remain separate work.

## Classification contract

`PolynomialTheorySubsumptionClassifier` receives a left and right expression.
It invokes the expression factorization adapter on the left side. That adapter
creates a `FactorizationRequest`, executes the selected engine through
`FactorizationVerifier`, and exposes only verifier-issued candidates. The right
side is accepted only when its canonical semantic value matches one of those
verified generated representations.

The result has one of five statuses:

- `THEORY_SUBSUMED`: the configured bounded theory generated and independently
  product-verified a matching decomposition.
- `NOT_SUBSUMED`: no matching verified candidate was generated inside the
  declared supported bound.
- `UNSUPPORTED`: the expression, coefficient domain, shape or requested
  capability lies outside the supported fragment.
- `BUDGET_INCONCLUSIVE`: engine or verifier work was exhausted; no negative
  mathematical conclusion is authorized.
- `TECHNICAL_FAILURE`: engine output, rendering or an internal contract was
  invalid; the result must not be treated as a normal theory miss.

A positive classification retains:

- the exact factorization-engine method ID;
- the canonical source expression;
- the verified generated expression selected for replay;
- the verifier-issued certificate hash;
- the application key and complete arithmetic work;
- `ProjectInventoryNovelty.NOT_EVALUATED`;
- `RetentionDisposition.DERIVED_MACRO_CACHE_ONLY`.

`Classification` has no public constructor. Only a completed classifier
invocation can issue one. A cache caller therefore cannot manufacture a
positive status around an unrelated pattern, certificate or application key.
Malformed engine output or an unparseable factorization rendering becomes
`TECHNICAL_FAILURE`, not a misleading negative result.

The classifier does not call a broad external equivalence oracle. It recognizes
only representations generated by the declared exact factorization method and
accepted by the independent product verifier. This keeps theory subsumption
distinct from arbitrary semantic equality and makes the information boundary
reviewable.

## Derived macro cache

`PolynomialDerivedMacroCache` is a deterministic owner-scoped cache. It is not
the rule kernel and not the ordinary persistent inventory.

A cache entry is keyed by the exact theory-derived macro identity:

- canonical source expression;
- deterministic generated expression;
- theory method;
- verifier certificate hash.

The runtime application key is intentionally not part of the macro identity.
Different observations of the same exact theory result therefore share one
capacity slot while retaining their primitive paths and provenance separately.

The cache API does not accept independent left and right patterns. Those values
come directly from the classifier-issued positive result, preventing a
certificate for one concrete identity from being attached to a different
generalized pattern. A generalized pattern can be cached only after the
classifier has replayed and verified the configured theory on that generalized
pattern itself.

Repeated observations of the same macro occupy one capacity slot. Distinct
content-addressed lineage records retain:

- the exact theory application key;
- the complete arithmetic work associated with the verified factorization;
- primitive rule IDs supplied by the producing path;
- source path, generation or other provenance identifiers.

Insertion order is deterministic. When capacity is exceeded, the oldest
distinct macro is evicted. Eviction and cache misses have no mathematical
meaning.

## Safety and claim boundary

This slice establishes only that a bounded configured theory can reproduce a
specific observed representation, that the proposed product was independently
reconstructed in the source ring, and that the result can be retained
separately as a performance cache entry.

It does not establish:

- external mathematical novelty;
- novelty relative to the project inventory;
- complete polynomial factorization;
- irreducibility of generated factors;
- equivalence outside the verified generated candidate set;
- correctness of caller-supplied primitive lineage by itself;
- production authorization of learned rules;
- a search-performance improvement.

A backend claim to completeness or irreducibility does not strengthen the
subsumption classification to independent evidence. A template miss is not an
irreducibility result.

The product learning pipeline is intentionally unchanged. Automatic diversion
from normal promotion into the derived cache requires a later integration slice
with explicit authorization evidence and an ablation against on-demand theory
synthesis.
