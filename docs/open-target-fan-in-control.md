# Cross-observation fan-in control on the public production campaign

Freeze the comparison on the existing public #355 production campaign. Its production outcome is already public. This retrospective control studies formation on these inputs. It does not evaluate cross-family generalization, sealed data, independent novelty, proof, or the other discovery-component ablations.

Run the ordinary pinned generation once per replay. Both arms consume exactly its same target-free immutable observations, seed catalog, inventory, search limits and two formation decisions. Preserve the full batch and the preregistered alpha-equivalent rejection pair, their exact observation and snapshot identities, and the original allocation of twelve candidate slots and two batch dispatches. In the production arm allow the miner to group observations by convergent path signature. In the ablated arm include observation identity in that same grouping key so no group mixes observations. Keep path extraction, support thresholds, alpha diversity, candidate grammar, generalizer and scoring unchanged. Neither arm can use validation, proof or labels to form candidates. Charge one mining dispatch per branch in both arms and record each rejected cluster, including zero-candidate branches.

Record both complete mining receipts per arm, actual admitted candidates, support, observation provenance, rejection reasons and all unused slots. Compare production output with the unmodified production runner and replay the full comparison in fresh processes. Report actual generated/explored states and mining calls separately from dispatch allowances. Do not infer an equal runtime or a general discovery advantage from a change in candidate count.
