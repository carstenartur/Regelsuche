# Deterministic showcase FINAL TEST generator

Status: **development characterization only; no public randomness consumed**  
Tracked by: [#597](https://github.com/carstenartur/Regelsuche/issues/597)

## Purpose

The generator turns one already-authorized `showcase-seed-receipt.json` into the
complete 24-case showcase FINAL TEST. It has no network access and no tuning
input. Every configuration later receives the exact same generated cases.

The generator cannot create or repair a seed. The seed receipt must already
bind the frozen plan, frozen candidate, verified drand receipt, chain and round.
The generated artifact remains:

```text
FINAL_TEST_GENERATED_NOT_EXECUTED
```

Generation is not a successful showcase result and authorizes no mathematical
novelty, importance or publication-grade benchmark claim.

## Frozen surface

The plan fixes three families with eight cases each and two variants at every
difficulty level 3, 4, 5 and 6:

1. `nested-rational-cancellation`
   - chains quotients with shared denominator factors;
   - requires flattening, cancellation and correct nonzero assumptions.
2. `factor-cancel-collect`
   - combines difference-of-squares factorization, cancellation and collection
     over a shared denominator.
3. `multi-stage-rational-polynomial`
   - alternates mixed-denominator ratios and factorable polynomial quotients;
   - forces several transformations to compose in the right order.

The cases are generated by construction from exact rational identities. The
ordinary app test also sends every generated fixture case through the production
`RationalFunctionNormalFormEquivalencePortAdapter` and requires:

```text
status = CONFIRMED
missing assumptions = []
unsupported assumptions = []
```

## Determinism and identity

Each case is derived independently from domain-separated SHA-256 material that
binds:

- the final derived seed;
- family identity;
- difficulty level;
- variant.

The output retains:

- concrete input and target expressions;
- normalized explicit assumptions;
- bounded coefficient vector and block topology;
- structural fingerprint;
- per-case content hash;
- family roots and one complete case-content root.

The generator rejects duplicate case IDs, content hashes, inputs or structural
fingerprints. Manual replacement, pruning and selective regeneration are
forbidden.

## Development self-test

The self-test uses a visibly synthetic seed receipt and therefore does not
consume the future showcase FINAL TEST:

```bash
python3 scripts/generate-proof-carrying-showcase-cases.py \
  --plan research/showcase/proof-carrying-self-improvement/showcase-plan.json \
  --self-test
```

It requires:

- byte-identical repeated generation;
- a changed case root after seed substitution;
- exactly 24 cases;
- exactly three balanced eight-case families;
- every frozen difficulty level in every family;
- strict content-hash roundtrip.

A development fixture may be written outside retained evidence:

```bash
python3 scripts/generate-proof-carrying-showcase-cases.py \
  --plan research/showcase/proof-carrying-self-improvement/showcase-plan.json \
  --self-test \
  --output build/showcase-development/generated-final-test.json
```

## Real generation

Only after a real candidate and verified future randomness have produced the
seed receipt may the real artifact be generated:

```bash
python3 scripts/generate-proof-carrying-showcase-cases.py \
  --plan research/showcase/proof-carrying-self-improvement/showcase-plan.json \
  --seed-receipt showcase-seed-receipt.json \
  --output generated-final-test.json
```

After this command, cases may be inspected but not replaced. The next allowed
stage is the one complete paired execution matrix against every frozen
configuration.

## Schema

`docs/schemas/regelsuche-proof-carrying-showcase-generated-final-test-v1.schema.json`
uses JSON Schema Draft 2020-12, rejects unknown fields and pins the exact family,
count, identity, no-pruning and pre-execution statuses. Runtime verification
additionally recomputes all per-case and aggregate hashes.
