# General Java mathematics integration: corrective implementation

## Binding requirement
Sandbox translates source Java and its semantics. Regelsuche alone searches mathematical representations of the supplied computation graph. No task selector, source-class recognizer or supplied solution derived from a showcase belongs in the adapter. Previous constructor-modular-provenance packages containing DivisibilityLoopProof / ConstructorModularFacts / ConstructorModularReview are withdrawn as the implementation direction; they are not evidence of general inference and must not be imported as product functionality.

## Implementation sequence
- [ ] Connect the existing general core RewriteRule catalog to the existing JointPlanSearch through a typed expression bridge. Preserve independent Java-numeric verification, original source traces, all outputs and budgets. No second search frontier, test-name lookup, string-formatted source preprocessing or hand-translated target formula.
- [ ] Test default catalog dispatch, multi-step algebra, generated input graphs with fresh names, overflow, casts, division boundaries, invalid contributions, cancellation and candidate limits.
- [ ] Keep sandbox source extraction independent of mathematical solution families; exclude compile-time-only edits while retaining runtime-initialized fields. Add a cross-repository end-to-end consumer gate with exactly the shipped SDK.
- [ ] Remove the withdrawn adapter/proposal path from any combined deliverable; preserve previously validated generic extraction, emission and explanations.
- [ ] Generic control-flow/method-summary inference is a separate remaining capability. Do not replace its absence with a loop recognizer, a fabricated proof or an unconditional proposal. Report unsupported semantics explicitly.

## Scope and evidence discipline
Elementary algebraic rules are reusable mathematics, not application-specific tasks. The catalog must be selected independently of the example and the independent checker is authoritative even for contributed rules claiming equivalence. Java division, effects, narrowing, floating point and resource bounds must not be silently turned into real-number algebra. Original evaluation traces remain untouched.

Tests may use known identities but cannot install a production recognizer for them. Generated and held-out corpora are additional evidence, not proof that every program can be optimized. Native screenshots and performance claims follow real execution only. No new product CI workflow is required.
